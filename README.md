# دارویاب ـ پروژه‌ی بازنویسی

نسخه‌ی جدید دارویاب با ASP.NET Core MVC و .NET 10. این پروژه محل توسعه‌ی قابلیت‌های جدید است؛ دو پروژه‌ی قدیمی‌تر در همین فضای کاری منابع مرجع هستند، نه مقصد تغییرات.

## نقشه‌ی سه پروژه

| پروژه | نقش در توسعه‌ی نسخه‌ی جدید | موارد قابل مراجعه |
|---|---|---|
| `darooyab_build_expired` | مرجع رفتار و محصول قدیمی روی .NET Framework 4.8 | صفحه‌ی خانه و صفحات موجود، متن‌ها و جریان‌های کاربری، URLها و دارایی‌های تصویری قدیمی |
| `darooyab_expired` | مرجع داده‌ی قدیمی‌تر ASP.NET Core | مدل‌ها، موجودیت‌ها، نگاشت‌های EF و قرارداد `darooConContext` |
| `darooyab_rewrite` | تنها مقصد پیاده‌سازی نسخه‌ی جدید روی .NET 10 | MVC، Viewها، سرویس‌ها، ViewModelها، CSS/JS و اتصال کنترل‌شده به پایگاه‌داده |

### روال کار برای درخواست‌های بعدی

1. ابتدا قابلیت در پروژه‌ی .NET Framework 4.8 را پیدا کن تا رفتار و انتظار محصول روشن شود؛ در صورت نیاز تصاویر و منابع ثابت مجاز را از آن شناسایی کن.
2. اگر کار به داده وابسته است، موجودیت و نگاشت متناظر را در پروژه‌ی `darooyab_expired` بررسی کن. وجود یک مدل یا `DbSet` به‌تنهایی به معنای آماده‌بودن query، سرویس یا رفتار UI نیست.
3. تغییر را در `darooyab_rewrite` و با الگوهای ASP.NET Core/.NET 10 انجام بده. قرارداد داده‌ی موجود را حفظ کن، اما کد کنترلر/صفحه‌ی قدیمی یا اجزای مختص .NET Framework را کورکورانه منتقل نکن.
4. پروژه‌های مرجع را فقط برای مطالعه بخوان؛ تغییرشان نده، مگر کاربر صریحاً همان تغییر را خواسته باشد. schema پایگاه‌داده نیز بدون درخواست و بررسی جداگانه تغییر نمی‌کند.
5. هیچ المان، ساختار، قابلیت، محتوا، metadata، سبک یا دارایی موجود را حذف یا تضعیف نکن؛ تغییرات را فقط در محدوده‌ای اعمال کن که پرامت صریحاً درخواست کرده است. حذف یا جایگزینی فقط وقتی مجاز است که خود پرامت همان حذف/جایگزینی را روشن و مشخص بخواهد. پیش از هر تغییر، وابستگی‌ها و رفتارهای موجود را بررسی و در پیاده‌سازی حفظ کن.
6. قابلیت را از ابتدا تا انتها بررسی کن: داده و خطا، endpoint/route، ViewModel، رابط، موبایل، دسترس‌پذیری و مستندات. اگر بخشی هنوز پیاده نشده، آن را فعال یا آماده‌ی استفاده نشان نده.
7. از دارایی‌های تصویری موجود در پروژه‌ی قدیمی فقط پس از تطبیق محتوا، مقصد و مجوز استفاده بهره بگیر. رازها و مقادیر اتصال را در فایل، مستندات یا خروجی‌ها ننویس.

این مرزبندی حاصل بررسی سه پروژه در جریان توسعه‌ی این سشن است: پروژه‌ی اول نشان می‌دهد محصول فعلی چه رفتار و محتوایی داشته، پروژه‌ی دوم منشأ مدل‌ها و DbContext منتقل‌شده است و پروژه‌ی سوم بستر نهایی بازنویسی است. مسئولیت «مرجع رفتار»، «مرجع داده» و «محل تغییر» را با یکدیگر اشتباه نگیر.

## وضعیت فعلی و مرز قابلیت‌ها

### پیاده‌سازی‌شده

- ASP.NET Core MVC روی `net10.0` و `darooConContext` منتقل‌شده.
- Bootstrap RTL نسخه‌ی 5.3.8 به‌صورت محلی؛ همه‌ی صفحات عمومی به‌جز صفحه‌ی نخست از Layout دو ستونه‌ی موجود با Sidebar و منوی Offcanvas موبایل استفاده می‌کنند. `_ViewStart.cshtml` این Layout را پیش‌فرض می‌گذارد و تنها صفحه‌ی نخست مستقیماً `_Layout` تک‌ستونه را انتخاب می‌کند.
- منوی اصلی سربرگ با همان ترتیب و زیرمنوهای Layout عمومی پروژه‌ی مرجع قدیمی؛ پیوندهای دارای مقصد قدیمی ولی فاقد route در بازنویسی فعلاً حفظ شده‌اند و پیاده‌سازی route و صفحه‌ی مقصد در مراحل بعدی انجام می‌شود.
- پوسته‌ی دو ستونه‌ی راست برای همه‌ی صفحات عمومی به‌جز صفحه‌ی نخست، شامل جست‌وجو، فهرست و جزئیات داروخانه، صفحات دارو و بخش‌های سایت؛ سایدبار خبرها، آگهی‌های حمایت‌شده، تازه‌های دارویی و داروهای پرمصرف را از موجودیت‌های همین DbContext می‌خواند. تازه‌های دارویی به صفحه‌ی برند و داروهای پرمصرف به صفحه‌ی ژنریک پیوند دارند؛ آگهی‌های عمومی نیز بدون برچسب تکراری «آگهی» نمایش داده می‌شوند. View عمومی تازه باید همین Layout را حفظ کند.
- صفحه‌ی خانه با ترتیب Medical Editorial، آخرین خبرهای متصل به دیتابیس، معرفی‌های حمایت‌شده، شش لوگوی شرکت و بخش اپلیکیشن؛ آمار ثابت حذف شده است.
- صفحه‌ی راهنمای اطلاعات دارویی روی `/Home/Section/drugs` با جست‌وجوی زنده‌ی مشترک، توضیح تفاوت صفحات ژنریک/برند، فهرست ژنریک‌های پرمصرف و برندهای تازه‌افزوده‌شده؛ فهرست‌ها از داده‌ی واقعی ساخته می‌شوند و metadata و CollectionPage JSON-LD دارند. ترتیب پرمصرف‌ها مطابق خروجی نهایی مرتب‌سازی مرجع قدیمی بر اساس شناسه‌ی دارو نزولی است؛ داده‌ی زنده به اتصال مجاز پایگاه‌داده وابسته است.
- پنج خبر فعال صفحه‌ی خانه و فهرست اخبار روی `/NewsApp` از `DarooyabAppNews` بر اساس `OrderIndex` نزولی دریافت می‌شوند؛ فهرست با صفحه‌بندی ۱۰تایی و metadata صفحه‌ی مرجع قدیمی پیاده‌سازی شده و مسیر جزئیات یک خبر نیز وجود دارد. خواندن زنده به اتصال مجاز پایگاه‌داده وابسته است.
- JSON-LD صفحه‌ی جزئیات خبر (`NewsArticle` و `VideoObject` اختیاری)، ژنریک (`MedicalWebPage` و `Drug`)، برند (`MedicalWebPage` با ارجاع `mainEntity`) و داروخانه مطابق شکل و کلیدهای Schema.org در Viewهای قدیمی تولید می‌شود. در جزئیات داروخانه، حالت عادی `Pharmacy` و حالت IRC گراف `Pharmacy` + `IndividualProduct` + `Offer` را می‌دهد. داده‌های پویا با `System.Text.Json` serialize می‌شوند؛ متن خبر پیش از استخراج `articleBody` sanitize شده و URL ویدئو فقط برای HTTP(S) معتبر وارد schema می‌شود. تاریخ/تصویر ناموجود جعل نمی‌شود.
- صفحه‌ی اطلاعات ژنریک دارو با الگوی legacy یعنی `/G-{DrugId}/{EngGenericName}`؛ داده‌ها از `DrugsName`، نمای `DrugInfo` و موجودیت‌های هم‌گروه `darooConContext` خوانده می‌شوند.
- صفحه‌ی اطلاعات برند با مسیر قدیمی `/B-{IRC}/{BrandEngName}`؛ IRC به رکورد انگلیسی معتبر وصل می‌شود و نامک نادرست به نشانی استاندارد هدایت می‌شود. صفحه از مشخصات `TBL_BrandAttribute`، نام‌ها و داده‌های ژنریک، شرکت/کشور، تصاویر، توضیحات، برندهای مرتبط و دیدگاه‌های تأییدشده استفاده می‌کند و متادیتای canonical، Open Graph، Twitter و MedicalWebPage دارد.
- جست‌وجوی مشترک دارو در سربرگ با پیشنهادهای حداکثر ۱۰ موردی و صفحه‌ی نتایج صفحه‌بندی‌شده روی مسیر `/Search?SearchText=...`؛ اتصال زنده به پایگاه‌داده باید در محیط توسعه/آزمون دارای اتصال معتبر تأیید شود.
- فهرست تازه‌های دارویی روی `/NewDrugs` با منطق اتصال برند فارسی و انگلیسی، ژنریک و اطلاعات تکمیلی پروژه‌ی مرجع؛ ترتیب شناسه‌ی رکورد نزولی و اندازه‌ی صفحه ۱۰ مورد است. صحت داده‌ی زنده تا آزمون با اتصال مجاز توسعه/آزمون تأیید نشده است.
- فهرست شرکت‌های تولیدکننده‌ی ایرانی و خارجی روی `/Pharmaceuticalcompanies` با query داده‌ی واقعی و منطق فیلتر، شمارش محصول، رتبه‌بندی و canonical پروژه‌ی مرجع؛ پیوند هر شرکت به `/Pharmaceuticalcompanies/{id}` جزئیات محصولاتش را با همان فیلتر مرجع نشان می‌دهد.
- فهرست شرکت‌های واردکننده روی `/ImporterCompanies`؛ طبق اکشن مرجع فقط شرکت‌های ایرانی با فرآورده‌های برند دارای IRC و زبان غیرِ خارجی نمایش داده می‌شوند و ترتیب رتبه سپس تعداد محصول نزولی است؛ `/ImporterCompanies/{id}` جزئیات محصولات را با کلید واردکننده می‌خواند.
- فهرست شرکت‌های توزیع‌کننده روی `/DistributerCompanies`؛ طبق اکشن مرجع شرکت‌های داخلی با نوع فعالیت ۴ نمایش داده می‌شوند، تعداد فرآورده‌های برند دارای IRC و زبان غیرِ خارجی بر اساس تولیدکننده محاسبه می‌شود و ترتیب رتبه سپس تعداد محصول نزولی است؛ `/DistributerCompanies/{id}` جزئیات محصولات مرتبط با تولیدکننده را نمایش می‌دهد.
- صفحه‌های جزئیات شرکت‌ها نام برند و ترجمه‌ی فارسی، تولیدکننده، ژنریک و تصویر موجود را با لینک به صفحات برند/ژنریک نشان می‌دهند؛ در موبایل جدول به کارت تبدیل می‌شود. عنوان SEO و canonical مسیر شرکت مطابق صفحه‌ی قدیمی است. اطلاعات سازمانی اختیاری از `TblOrganizationDetails` به‌صورت متن امن رندر می‌شوند. درخواست‌های فقط‌خواندنی فهرست و جزئیات هر سه دسته در محیط توسعه با اتصال پیکربندی‌شده پاسخ موفق دادند؛ این آزمون تضمین‌کننده‌ی کامل‌بودن داده یا موجودی لحظه‌ای نیست.
- فهرست گروه‌های مارتیندل روی `/DrugGroups` با ترتیب طبیعی خروجی مرجع قدیمی (بدون مرتب‌سازی تازه) و صفحه‌ی داروهای هر گروه روی `/DrugGroups/{id}`؛ صفحات از گروه‌ها و داروهای ژنریک مرتبط در `darooConContext` استفاده می‌کنند. جزئیات گروه مانند مرجع در دسکتاپ جدول و در موبایل کارت همراه تصویر/نام‌های ژنریک است؛ canonical و title قدیمی حفظ شده‌اند.
- `/HerbalMedicines` فهرست برندهای دارویی گروه ۵۲ را با IRC و ترجمه‌ی فارسی/انگلیسی نمایش می‌دهد؛ `/DrugHerbal` مستقل از آن فهرست ژنریک/نام علمی گیاهان همان گروه است. هر دو مسیر route، canonical و نمایش جدول دسکتاپ/کارت موبایل مطابق شاخه‌ی مربوط در مرجع دارند و صفحه‌ی گیاهان به مسیر ژنریک پیوند می‌دهد.
- فهرست متخصصان سلامت روی `/doctors` و `/doctors/{page}` و جزئیات عمومی روی `/profile/{id}`؛ فیلتر تأیید IRIMC، فعالیت‌های ۲/۴/۶/۹/۱۱، حذف حساب‌های حذف‌شده و نام‌های کوتاه، ترتیب تخصص/فعالیت و شناسه، صفحه‌بندی ۲۰تایی، نشانی‌های عمومی و اطلاعات تخصص مطابق مرجع اجرا شده‌اند. canonical و description قدیمی حفظ شده‌اند؛ نام‌ها در فهرست به جزئیات پیوند دارند و route جزئیات نیز فقط پروفایل‌های تأییدشده را نمایش می‌دهد.
- فهرست داروخانه‌های تأییدشده روی `/داروخانه` با فیلترهای استان و شهر از `Category` (شهر با `Type = Township` و `ParentID` استان)، منطقه از `DarooyabCityDistricts`، حوزه‌ی دارویی و نام؛ تغییر استان/شهر، فهرست وابسته را به‌صورت زنده به‌روز می‌کند. این موجودیت‌ها مطابق اکشن‌های متناظر صفحه‌ی داروخانه در پروژه‌ی مرجع انتخاب شده‌اند. ترتیب رتبه‌بندی قدیمی حفظ شده و صفحه‌بندی از `PagedResult<T>`، افزونه‌ی `ToPagedResultAsync` و partial مشترک استفاده می‌کند. خواندن زنده‌ی داده به اتصال مجاز پایگاه‌داده وابسته است.
- فهرست موجودی ژنریک در `/availability/{DrugId}` و موجودی برند در `/availability/IRC/{IRC}` با فیلترهای استان، شهر، منطقه و حوزه‌ی دارویی پیاده‌سازی شده‌اند؛ صفحه‌ی برند فیلتر «سایر برندها از همین شکل دارویی» را نیز دارد. مسیر استان با slug معتبر مشابه مرجع قدیمی پشتیبانی می‌شود. نتایج و ترتیب آنها مستقیماً از Stored Procedureهای متناظر می‌آیند؛ فقط SPهای دارای ورودی صفحه/اندازه و شمارنده‌ی کل برای صفحه‌بندی استفاده می‌شوند، و لینک‌های صفحه فیلترها را حفظ می‌کنند. title، description، canonical و Open Graph مطابق metadata صفحه‌ی قدیمی تولید می‌شوند. داده‌ی زنده به اتصال مجاز پایگاه‌داده وابسته است.
- جزئیات داروخانه با مسیر قدیمی `/ph-{pharmacyId}/{pharmacyName}` پیاده‌سازی شده است؛ نامک نادرست به مسیر استاندارد هدایت می‌شود. در کارت تماس، نشانی و راه‌های ارتباطی پیش از گالری تصاویر نمایش داده می‌شوند و کارت ارجاع‌های فعال تمام‌عرضِ ستون محتوای اصلی در ادامه قرار دارد. گالری در صفحات عادی و دارای IRC، در صورت وجود چند تصویر با اسلایدر Scroll Snap و کنترل‌های دسترس‌پذیر نمایش داده می‌شود و تصویر یگانه بدون کنترل باقی می‌ماند. با query پارامتر `IRC`، صفحه‌ی برند/وضعیت ارجاع به‌شکل جداگانه رندر می‌شود و موجودی فقط از درخواست ارجاع معتبر با تاریخ انقضای فعال گزارش می‌شود. canonical، description و ساختار Schema.org مطابق حالت صفحه تنظیم می‌شوند. داده‌های زنده‌ی این مسیر تا زمان آزمون با اتصال مجاز توسعه/آزمون تأییدشده محسوب نمی‌شوند.
- در صفحه‌ی جزئیات دارای `IRC`، فهرست «سایر داروخانه‌هایی که این دارو را اعلام موجودی کردند» از ارجاع‌های فعال همان IRC خوانده می‌شود؛ فیلتر استان/شهر، حذف دانشگاه‌هایی که داروی مربوطه را با وضعیت مخفی‌شده‌ی سازمان غذا و دارو ثبت کرده‌اند، و ترتیب رتبه‌ی موجودی از منطق Partial قدیمی پیروی می‌کنند. در تساوی رتبه، شناسه‌ی درخواست برای ثبات نتایج ملاک است.
- نشان رتبه‌ی تضمین موجودی در جزئیات داروخانه با IRC و کارت سایر داروخانه‌های اعلام‌کننده از فایل‌های محلی `wwwroot\Content\Images\ranking1.webp` تا `ranking10.webp` استفاده می‌کند؛ تصویر متناسب با رتبه، alt دسترس‌پذیر و اندازه‌ی واکنش‌گرا دارد. اگر رتبه‌ای خارج از بازه‌ی تصاویر موجود باشد، عدد رتبه به‌صورت متن نمایش می‌یابد و تصویر رتبه‌ی نادرست استفاده نمی‌شود.
- صفحه‌ی دارو بخش‌های عمومی/تخصصی، بارداری، اشکال دارویی، نام‌های تجاری، داروهای هم‌گروه و دیدگاه‌های تأییدشده را نمایش می‌دهد؛ تب‌ها زیر سربرگ ثابت می‌مانند و بخش جاری را هنگام پیمایش مشخص می‌کنند. در موبایل تب‌ها دو ردیف هستند و تب داروهای هم‌گروه فعلاً مخفی است؛ با حذف قاعده‌ی `.drug-tab-related` در breakpoint موبایل دوباره نمایش داده می‌شود. آگهی‌ها در ستون جانبی و با برچسب تبلیغاتی جدا هستند.
- صفحه‌ی ژنریک فهرست سرفصل‌های محتوای دارو را پس از رندر، از headingهای قابل مشاهده می‌سازد و در صورت نبود سرفصل، فهرست را پنهان می‌کند. موجودی ثبت‌شده‌ی دارو در صفحه‌ی مستقل `/availability/{DrugId}` نمایش داده می‌شود و به‌عنوان موجودی لحظه‌ای تضمین‌شده معرفی نمی‌شود.
- صفحه‌ی تماس روی `/Contactus` راه‌های ارتباطی ثبت‌شده در مرجع قدیمی و فرم پیام متصل به `TblContactus` را ارائه می‌کند؛ ثبت فرم دارای اعتبارسنجی، ضدجعل درخواست، honeypot و محدودیت نرخ است و موضوع‌ها از دسته‌های `Activity` خوانده می‌شوند. در خطای پایگاه‌داده فرم با پاسخ خطای سرویس غیرفعال می‌شود؛ ضداسپم سبک جایگزین CAPTCHA قدیمی نیست. متادیتای title، description و canonical صفحه از مرجع حفظ شده‌اند. نشانی خیابانی یا نقشه نمایش داده نمی‌شود چون در مرجع معتبر نبود.
- صفحه‌ی `/About` معرفی ثابتی از بخش‌های موجود دارویاب، هشدار عدم جایگزینی اطلاعات دارویی با مشورت متخصص و پیوند به بخش‌های مرتبط دارد؛ صفحه‌ی مرجع قدیمی فقط متن نمونه‌ی پیش‌فرض داشت و متادیتای SEO آن به عنوان `About` محدود بود، بنابراین ادعا یا اطلاعات تأییدنشده‌ای از آن منتقل نشده است.
- تصاویر صفحه‌ی نخست در `wwwroot\images\home` قرار دارند.
- لوگوهای سازمانی پروژه‌ی قدیمی در `wwwroot\Content\OrganizationDetailLogo` قرار می‌گیرند تا URLهای ذخیره‌شده با پیشوند `/Content/OrganizationDetailLogo/` در static files پروژه‌ی جدید معتبر بمانند. از پوشه‌ی مرجع موجود در این workspace پنج فایل کپی شده است؛ لوگوهای ارجاع‌شده در داده که فایل متناظرشان در پروژه‌ی مرجع موجود نیست، با این کپی قابل بازیابی نمی‌شوند.
- F5 و پروفایل‌های توسعه روی `http://0.0.0.0:5264` گوش می‌دهند تا از طریق هر IPv4 قابل‌دسترسی سیستم، از جمله شبکه‌ی محلی، باز شوند؛ در توسعه به HTTPS محلی هدایت نمی‌شود. دسترسی از دستگاه دیگر به IP شبکه‌ی میزبان و مجازبودن پورت در فایروال نیاز دارد.

### هنوز قابلیت عملیاتی محسوب نمی‌شوند

- مسیرهای منوی قدیمی که هنوز در بازنویسی route ندارند و باید در مراحل بعدی پیاده‌سازی شوند: `/App`، `/ph/login`، `/page?Id=110`، `/doctorpanel/login` و `/ClassificationAHFS`. لینک مجوزها همچنان به نشانی خارجی پروژه‌ی قدیمی اشاره دارد.
- کد جست‌وجوی دارو پیاده شده، اما نتیجه‌ی واقعی، کیفیت تطبیق، کارایی query و صفحه‌بندی هنوز با اتصال معتبر به پایگاه‌داده‌ی توسعه/آزمون تأیید نشده است؛ تا آن زمان کیفیت عملیاتی آن تضمین‌شده نیست. نتیجه‌هایی که IRC و رکورد انگلیسی متناظر دارند به صفحه‌ی برند هدایت می‌شوند.
- مسیر و نمایش صفحه‌ی برند پیاده‌سازی شده‌اند، اما داده‌های زنده‌ی برند و کیفیت روابط آن نیز تا زمان آزمون با اتصال مجاز توسعه/آزمون تأیید عملیاتی نشده‌اند.
- صفحه‌ی داروهای کمیاب هنوز محتوای عمومی/آماده‌سازی دارد. صفحه‌ی راهنمای اطلاعات دارویی (`/Home/Section/drugs`)، فهرست داروخانه‌ها، فهرست اخبار (`/NewsApp`) و صفحات جزئیات داروی ژنریک (`/G-{DrugId}/{EngGenericName}`) و برند (`/B-{IRC}/{BrandEngName}`) از این محدودیت مستثنا هستند.
- نتیجه‌ی زنده‌ی فهرست ارجاع‌های صفحه‌ی ژنریک، فهرست داروخانه و جزئیات آن‌ها تا آزمون با اتصال مجاز توسعه/آزمون تأیید نشده است. این ارجاع‌ها وضعیت ثبت‌شده در منبع داده را نشان می‌دهند و تضمین موجودی فعلی نیستند.
- ثبت دیدگاه در صفحه‌ی دارو فعال نیست؛ به سازوکار ضداسپم/کپچای پروژه‌ی قدیمی وابسته بود و تا مهاجرت امن آن، فرم ارسال نمایش داده نمی‌شود.
- نشانی بعضی تصاویر خبر در پایگاه‌داده ممکن است 404 شود؛ Fallback رابط جلوی تصویر شکسته را می‌گیرد، اما جایگزین اصلاح منبع داده نیست.
- برای هر صفحه‌ی جدید، metadata و تگ‌های SEO صفحه‌ی متناظر در پروژه‌ی مرجع باید بررسی و در نسخه‌ی جدید بازپیاده‌سازی شوند؛ از جمله عنوان، توضیحات، canonical، تگ‌های اجتماعی و داده‌ی ساختاریافته. هر داده‌ی SEO باید از منبع معتبر و با serialize امن تولید شود.
- ترتیب نمایش تمام فهرست‌ها در نسخه‌ی جدید باید با منطق مرتب‌سازی صفحه/اکشن متناظر در پروژه‌ی مرجع برابر باشد؛ پیش از افزودن یا تغییر sort، ترتیب legacy را بررسی کن. برای فهرست داروخانه‌ها همان رتبه‌ی فعال، مجموع تراکنش کیف پول و نام داروخانه حفظ می‌شود و برای فهرست‌های دارای رتبه‌بندی ارجاع، اولویت رتبه‌ی موجودی قدیمی حفظ می‌شود.

## نقشه‌ی راه توسعه

نقشه‌ی راه و معیارهای پذیرش مرحله‌ای در [ROADMAP.md](./ROADMAP.md) نگهداری می‌شوند. اولویت فعلی، اعتبارسنجی قابلیت‌های متصل به داده با پایگاه‌داده‌ی مجاز توسعه/آزمون است؛ قابلیت‌هایی که منبع داده یا مسیر اجرایی ندارند تا زمان تکمیل و آزمون سرتاسری، فعال معرفی نمی‌شوند. برای این نقشه تاریخ انتشار فرض نشده است.

## جهت طراحی

- اسکلت اصلی **Medical Editorial** است: Hero و دسترسی‌های اصلی پیش از خبرها و معرفی‌های تبلیغاتی قرار دارند؛ جست‌وجوی مشترک در سربرگ در همه‌ی صفحه‌ها در دسترس است.
- رویکرد **Modern Pharmaceutical Platform** فقط به‌شکل محدود برای بلوک معرفی حمایت‌شده یا CTA اپ مناسب است؛ از تبدیل صفحه‌ی مرجع به داشبورد یا صفحه‌ی تبلیغاتی پرهیز کن.
- رنگ‌های سرمه‌ای، سبزآبی و سطوح روشن و توکن‌های رنگ/تایپوگرافی `site.css` را حفظ کن. متن‌های کمکی حداقل 13px هستند؛ آمار بدون منبع نمایش داده نمی‌شود.
- سلسله‌مراتب headingها را با توکن‌های `--font-size-h1` تا `--font-size-h6` در `site.css` حفظ کن؛ اندازه‌ی H2 باید در همه‌ی breakpointها از H3 بزرگ‌تر باشد. برای برچسب‌های نمایشی یا متن‌های کوچک از تگ heading استفاده نکن و استایل‌های اختصاصی heading را نیز بر اساس همین توکن‌ها تنظیم کن.
- همه‌ی Viewها باید در عرض 320px و breakpointهای موبایل، تبلت و دسکتاپ پاسخ‌گو باشند و اسکرول افقی ناخواسته ایجاد نکنند؛ از چیدمان متناسب محتوا به‌جای پنهان‌کردن سرریز استفاده کن.
- ترتیب صفحه‌ی خانه: Header و جست‌وجوی مشترک → اسلایدر بنرها → Hero → دسترسی سریع → آخرین مطالب → معرفی‌های حمایت‌شده با برچسب → لوگوهای شرکت‌ها → اپلیکیشن → Footer.
- طراحی فعلی را مرحله‌ای بهبود بده؛ بازنویسی کامل یا حذف دارایی‌های موجود هدف نیست.

### تصمیم‌ها و یافته‌های بازبینی بصری

- رویکرد منتخب برای ساختار اصلی **Medical Editorial** است؛ از کنتراست و بلوک‌های بصری **Modern Pharmaceutical Platform** فقط در معرفی اپ یا محتوای حمایت‌شده، با تفکیک و برچسب روشن، استفاده شود.
- رنگ اصلی سبزآبی سایت با توکن‌های `--primary` و `--primary-dark` حفظ شود. هرجا صفحه به رنگ مکمل نیاز دارد، از ترکیب تأکیدی گرمِ کهربایی همین طراحی با توکن‌های `--accent-warm` (`#db995b`) و `--accent-warm-soft` (`#fff5e9`) استفاده کن؛ این رنگ مکمل محدود به تأکیدها و سطوح ملایم باشد و جایگزین رنگ اصلی نشود.
- همه‌ی تاریخ‌های قابل‌مشاهده برای کاربر باید با تابع یگانه‌ی `PersianDateFormatter.Format` در `Utilities\PersianDateFormatter.cs` به شمسی نمایش داده شوند؛ در Viewها از همین تابع استفاده کن و تبدیل تاریخ را دوباره در View یا مدل دیگری پیاده‌سازی نکن. مقدار machine-readable/SEO مانند `datetime` می‌تواند ISO میلادی باقی بماند.
- اسلایدر و Company Intro پس از خبرها قرار دارند و معرفی‌ها با برچسب تبلیغاتی از تحریریه جدا شده‌اند.
- دسترسی‌های سریع در یک مجموعه ادغام شده‌اند؛ پیوند داروخانه به فهرست جست‌وجوپذیر و متصل به داده می‌رود و قابلیت مکان‌یابی نمایش داده نمی‌شود.
- کنترل Carousel فقط وقتی اسلاید قابل پیمایش باشد نمایش داده می‌شود؛ در حالت داده‌ی خالی/خطای خبر، کنترل خبرها حذف است.
- خبرهای 404شده باید Fallback قابل‌فهم داشته باشند؛ منبع URL تصویر همچنان نیازمند بررسی است. متن عنوان/خلاصه/تاریخ کارت‌ها باید خوانا و با کنتراست کافی بماند.
- کارت لوگو و بنرهای غیرتعاملی Hover تعاملی ندارند؛ لوگوها در شبکه‌ی منظم نمایش داده می‌شوند.
- آمار ثابت نصب از صفحه‌ی خانه حذف شده است؛ تا زمان تأیید منبع و تاریخ مبنا دوباره به‌عنوان داده‌ی جاری نمایش داده نشود.
- focus صفحه‌کلید، کنتراست متن‌ها و اهداف لمسی حداقل 44px در CSS مرکزی تعریف شده‌اند؛ در تغییرات بعدی حفظ شوند.
- Layout دو ستونه و Sidebar فعلی را حفظ کن، اما محتوای Sidebar را با بخش جاری متناسب کن. صفحات Stub باید حالت آماده‌سازی/غیرفعال بودن را صریح نشان دهند و به‌عنوان ابزار زنده معرفی نشوند.
- بلوک «دسترسی سریع» در پنل سمت راست فعلاً به‌صورت پیش‌فرض نمایش داده نمی‌شود، اما کد و پیوندهای آن حفظ شده‌اند؛ برای نمایش دوباره، `ViewData["ShowQuickAccess"]` را برای ViewComponent به `true` تنظیم کن.

## دارایی‌های تصویری

دارایی‌های منتقل‌شده از پروژه‌ی مرجع در `wwwroot\images\home`:

- `slider`: چهار بنر معرفی/اطلاع‌رسانی؛ مقصد و اعتبار هر بنر را پیش از استفاده مجدد بررسی کن.
- `company-intro`: چهار تصویر معرفی محصول/شرکت؛ از محتوای تحریریه‌ای جدا و در صورت حمایت‌شده‌بودن با برچسب روشن نمایش داده شوند.
- `promotions`: دو بنر معرفی محصول.
- `companies`: شش لوگوی شرکت دارویی.

فایل‌ها را صرفاً به‌خاطر تغییر طراحی حذف نکن. برای هر تصویر، alt متناسب، ابعاد/نسبت نمایش، کیفیت بارگذاری و اعتبار لینک را بررسی کن. پیش از استفاده از فایل فونت یا لوگوی دیگری از پروژه‌های قدیمی، مجوز و منشأ آن را تأیید کن.

## فناوری و وابستگی‌ها

- .NET 10، EF Core SQL Server 10.0.14، `DNTPersianUtils.Core` 7.0.2 و Bootstrap RTL 5.3.8.
- Bootstrap در `wwwroot\lib\bootstrap` میزبانی محلی می‌شود.
- فونت محلی Vazirmatn نسخه‌ی v33.003 از مخزن رسمی پروژه و تحت SIL Open Font License 1.1 استفاده می‌شود؛ فایل مجوز در `wwwroot\fonts\OFL.txt` قرار دارد و وزن‌های 400، 500، 600 و 700 در CSS مرکزی تعریف شده‌اند.
- برای اسلایدر و رفتارهای ساده‌ی رابط، CSS و JavaScript بومی موجود را ترجیح بده. Owl/jQuery UI یا کتابخانه‌ی تازه را بدون نیاز مشخص، سنجش دسترس‌پذیری و توجیه نگهداری اضافه نکن.
- قبل از افزودن dependency، قابلیت CSS/JS و packageهای فعلی را بررسی کن؛ کتابخانه‌ی نقشه فقط پس از نیازسنجی نمایش نقشه و انتخاب سرویس آن لازم خواهد بود.

## راه‌اندازی و اعتبارسنجی

از PowerShell در ریشه‌ی فضای کاری:

```powershell
dotnet build .\darooyab_rewrite\darooyab_rewrite.csproj
dotnet run --project .\darooyab_rewrite\darooyab_rewrite.csproj
```

در VS Code، پوشه‌ی `D:\Projects\Dotnet\darooyab_new` را باز و پروفایل `Darooyab Rewrite (.NET 10)` را با F5 اجرا کن. در همان سیستم از `http://localhost:5264` و از دستگاه دیگر با IP شبکه‌ی میزبان و پورت `5264` وارد شو؛ در صورت نیاز دسترسی ورودی این پورت را در فایروال مجاز کن. تنظیمات در `.vscode\launch.json` و `.vscode\tasks.json` هستند.

### اتصال پایگاه‌داده

`Program.cs` اتصال را از `ConnectionStrings:Darooyab` می‌خواند. برای توسعه‌ی محلی از User Secrets پروژه یا متغیر محیطی `ConnectionStrings__Darooyab` استفاده کن. مقدار واقعی اتصال در این README یا سورس نگهداری نمی‌شود. گواهی SQL Server محیط عملیاتی باید معتبر باشد؛ تنظیم‌های صرفاً توسعه را به محیط عملیاتی منتقل نکن.

### چک‌لیست تغییرات

- پیش از ویرایش، اجزای موجود و رفتارهای مرتبط را شناسایی کن؛ چیزی را خارج از محدوده‌ی صریح پرامت حذف، پنهان، جایگزین یا تضعیف نکن.
- Build پروژه‌ی هدف را اجرا کن؛ اگر پروژه‌ی آزمون مرتبط وجود دارد، آزمون محدود به تغییر را هم اجرا کن.
- رفتار را در عرض‌های 320، 390، 768، 1024 و 1440 پیکسل بازبینی کن؛ نبود سرریز افقی را تأیید کن.
- دسترسی صفحه‌کلید و focus قابل مشاهده، هدف لمسی، کنتراست متن، reduced motion، alt تصاویر، و حالت‌های loading/empty/error را بررسی کن.
- برای داده‌ی پایگاه‌داده، مسیر موفق، نبود داده و خطای اتصال را جداگانه اعتبارسنجی کن؛ خطا را به حالت موفقیت‌نما تبدیل نکن.
- تغییر مستندات مرتبط را همراه با تغییر قابلیت انجام بده. این README راهنمای وضعیت است؛ هرگاه وضعیت «پیاده‌شده/ناتمام» تغییر کرد، همین بخش را به‌روز کن.
